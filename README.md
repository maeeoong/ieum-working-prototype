# 이어봄 — 중단 후 복귀 UX PoC

사용자경험디자인2 5주차 개인과제. **이동 때문에 활동이 중단되어도 사용자가 원래 하려던 활동을 쉽게 이어갈 수 있는가?**를 검증하는 모바일 웹 Working Prototype입니다.

## 기준과 범위

최우선 기준은 `사용자 핵심 시나리오.pdf`의 출근·퇴근 흐름입니다. PRD와 Lo-fi는 화면 정보 위계와 저장·복귀 원칙을 보완하는 자료로만 사용했습니다. 경제·시사 공부, 읽기↔듣기 전환, 혼잡도에 따른 형태 제안, 음성 생성·재생은 포함하지 않습니다.

시간순 사용자 상황·행동·개입·화면 분석은 [시나리오 분석](docs/SCENARIO.md), 직접 검증 절차와 수용 기준은 [테스트 가이드](docs/TESTING.md)에 정리했습니다.

## 실행

Node.js 20 이상. 외부 패키지 설치와 API 키가 필요 없습니다.

```bash
npm run dev
```

`http://localhost:4173`을 엽니다. `index.html`을 파일로 직접 여는 대신 HTTP 서버를 사용하세요. 같은 Wi-Fi의 휴대폰에서는 개발 컴퓨터의 로컬 IP와 포트 4173으로 접속하거나, 배포된 HTTPS 주소로 체험할 수 있습니다.

```bash
npm test
npm run build
```

`build`는 배포 디렉터리 `dist/`와 JavaScript 구문을 검증합니다. 별도 번들링이 없는 HTML/CSS/ES modules 구조입니다.

## 체험 흐름

### 출근 · 전자책

1. 시작 화면의 `출근 · 전자책`에서 `이 책 이어읽기`를 선택합니다.
2. 도보 7분 구간에서는 선택한 책과 저장 위치만 보여줍니다.
3. `다음 상황`으로 승강장에 도착해 `2분 먼저 읽기` 또는 `탑승 후 이어읽기`를 선택합니다.
4. 읽기 화면의 좌우 버튼으로 실제 페이지를 바꿉니다. 132~151p의 창작 발췌문이 있습니다.
5. `다음 상황`으로 환승 직전과 환승 통로를 진행합니다. 직접 저장하지 않아도 위치를 저장하고 멈춥니다.
6. 두 번째 승강장의 RETURN POINT에서 표시된 페이지를 확인하고 한 번 눌러 이어읽습니다.
7. 두 번째 지하철에서도 같은 책을 유지합니다. 하차하면 이번 시작·종료 위치를 정리합니다.

### 퇴근 · 해리포터

1. `퇴근 · 해리포터`에서 오후 6시 30분의 알림 카드를 엽니다.
2. 도보 4분에는 재생을 요구하지 않습니다.
3. 승강장: 동료 메시지 → SNS 모의 피드 → `잠시 후 · 복귀 알림 받기`로 이동합니다.
4. “호그와트로 돌아갈 준비됐나요?” 알림에서 00:42:18부터 이어봅니다. 거절도 가능합니다.
5. 첫 지하철에서 모의 시청 시간이 초 단위로 진행됩니다. `테스트 도구 → 시청 시간 19분 진행`으로 긴 구간을 압축할 수 있습니다.
6. 환승에서 멈추고, 두 번째 승강장의 저장된 시간부터 한 번 눌러 이어봅니다.
7. 하차 후 모의 시청 위치와 이번 진행 시간을 확인합니다.

`테스트 초기화`는 활동 화면 하단 테스트 도구 또는 종료 화면에서 실행합니다. 두 활동의 저장 위치를 모두 지우고 출근 시작 화면으로 돌아갑니다. 확인창의 취소를 누르면 현재 상태를 유지합니다.

## 실제 작동하는 기능

- 출근·퇴근 별도의 시간순 상황 진행과 다음 구간 시뮬레이션
- 출근 승강장의 먼저 읽기 / 탑승 후 시작 선택
- 전자책 본문·페이지 이동 및 저장
- 퇴근 메시지·SNS 이탈·의도 상기 알림·복귀
- 모의 영상 타이머, 재생·정지, 동일 시청 위치에서 재개
- 환승 자동 일시정지, 직접 저장, RETURN POINT에서 한 번 눌러 복귀
- 브라우저 로컬 저장, 새로고침·재방문 후 위치 복원
- 다음 이동에서 이어가기와 테스트 초기화
- 앱을 백그라운드로 전환하면 일시정지하고 위치 보존

저장 범위는 동일 브라우저·동일 주소입니다. 기기·브라우저·포트가 달라지면 별도의 저장 공간을 사용합니다. 저장 접근이 제한되면 화면에서 안내합니다. 복원 시 자동 재생하지 않습니다.

## 원문을 재현하기 위한 대체와 축소

- 시나리오에 책 제목과 본문이 없어, 독서 조작을 위한 **창작 예시 책**을 사용했습니다. 새 활동을 추가한 것이 아닙니다.
- 해리포터는 시나리오에 등장하는 활동 이름만 사용합니다. **실제 영화·음원·포스터·OTT 연동은 없습니다.** 모의 플레이어에서 타이머가 실제로 진행·정지·저장됩니다. 화면에 시뮬레이션임을 표시합니다.
- 잠금화면 알림·SNS·메시지는 웹 내 모의 화면입니다. 운영체제 알림을 띄우거나 실제 메시지를 읽지 않습니다.
- 초기 활동 세 가지는 원문대로 표시합니다. 이번 출근 시나리오가 선택하는 전자책만 시작할 수 있고, 해리포터는 퇴근 흐름으로 체험합니다. 뉴스 흐름은 추가하지 않았습니다.
- 이동 구간 시간은 원문 범위입니다. 17~19분 등을 실제 기다리지 않고 `다음 상황`으로 넘깁니다. 시청 시간 19분 진행 버튼은 테스트 도구이며 실제 사용자 서비스 버튼이 아닙니다.
- 원문의 132p, 42:18은 기본 위치로 사용합니다. 이후 위치는 사용자의 조작에 따라 달라집니다. 42:18에서 19분을 진행하면 01:01:18이 되며, 일반 타이머로 진행된 초가 있으면 그만큼 더해집니다.
- 원문의 독서 32분, 132→151p, 퇴근 시청 40분, 주간 1시간 50분은 정해진 예시 값입니다. 실측한 것처럼 표시하지 않고, 체험 중 저장된 위치·모의 시청 시간만 결과에 표시합니다. 누적 통계는 핵심 복귀 검증에서 제외했습니다.

## GitHub와 Vercel

이 폴더 전체를 GitHub 저장소 루트에 업로드할 수 있습니다. 원본 수업 PDF와 개인 파일은 배포 소스에 포함하지 않았습니다.

Vercel에서 해당 GitHub 저장소를 가져온 뒤 다음 설정을 사용합니다. `vercel.json`에도 선언되어 있습니다.

- Framework preset: Other
- Build command: `npm run build`
- Output directory: `dist`
- Environment variables: 없음

현재 작업은 **업로드·배포 가능한 소스 준비**까지입니다. 원격 저장소 생성이나 실제 Vercel 배포는 수행하지 않았습니다.

## 구조

- `dist/index.html`: 문서와 앱 기본 틀
- `dist/content.js`: 출근·퇴근 구간, 예시 책, 시청 정보
- `dist/model.js`: 상태 전이·저장 복원 규칙
- `dist/app.js`: 화면·조작·모의 시청 타이머
- `dist/style.css`: 모바일 우선 레이아웃
- `tests/continuity.test.mjs`: 중단·복귀·저장·초기화 회귀 테스트
- `scripts/serve.mjs`: 로컬 미리보기 서버
- `docs/`: 시나리오 분석·수동 검증 가이드

## AI 활용 내역

OpenAI Codex를 협업 도구로 사용했습니다.

- 사용자가 제공한 PRD·핵심 사용자 시나리오·Lo-fi를 읽고 시간순 흐름과 PoC 범위를 정리했습니다.
- 초기 제안의 경제·시사 콘텐츠 및 읽기↔듣기 전환 방향은 사용자의 수정 요청으로 폐기했습니다. 최종 구현은 출근 전자책과 퇴근 해리포터의 **중단·복귀** 시나리오를 우선합니다.
- AI가 HTML/CSS/JavaScript 구현, 예시 전자책 발췌문, CSS 표지·모의 영상 화면, 상태 테스트, 문서 초안을 작성했습니다.
- 사용자가 핵심 목표·범위·시나리오 우선순위를 결정하고, 변경 방향을 검토·지시했습니다.
- AI가 자동 테스트와 브라우저 조작으로 구현을 점검하고 오류를 수정했습니다. 실제 참여자 사용성 연구를 수행하거나 실기기 검증 결과를 만들어 낸 것은 아닙니다.
- 음성 생성·재생, 실제 해리포터 영화·음원·포스터 사용, 외부 교통정보 연동은 최종 결과에 포함하지 않았습니다.
