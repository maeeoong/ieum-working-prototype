# 핵심 사용자 시나리오 시간순 분석

기준: 사용자가 제공한 `사용자 핵심 시나리오.pdf`. PRD와 Lo-fi보다 사용자 시나리오를 우선합니다.

검증 질문: **활동이 이동 때문에 중단되더라도 사용자가 원래 하려던 활동을 쉽게 이어갈 수 있는가?**

## 출근 — 피로도 3, 오전 8시

| 순서 | 사용자 상황·행동 | 서비스 개입 | 화면·인터랙션 |
|---|---|---|---|

| 2 | 역까지 도보 7분 | 독서를 강요하지 않음. 선택한 활동만 유지 | 준비 화면, 책·마지막 위치 |
| 3 | 첫 승강장 대기 2~4분 | 남은 시간에 맞춰 짧게 시작하거나 탑승 후 시작하도록 제안 | 2분 먼저 읽기 / 탑승 후 이어읽기 |

| 6 | 환승 통로 도보 5분 | 독서 중단·위치 저장. 끝난 것이 아니라 잠시 멈춘 상태 | 중단 상태, 저장된 책·페이지. 재개 강요 없음 |
| 7 | 두 번째 승강장 대기 2~4분 | 원래 활동을 가장 가까운 선택지로 제공 | RETURN POINT, 저장 위치, 한 번 눌러 이어읽기 |
| 8 | 두 번째 지하철 14~16분 | 환승 전 위치에서 재개. 이후 개입 없음 | 같은 전자책·페이지, 계속 읽기 |
| 9 | 하차 후 회사까지 도보 4분 | 더 읽게 하지 않고 활동 정리 | 시작→종료 페이지, 다음 이동에서 이어읽기 |

## 구현에서 명시적으로 대체한 부분

외부 앱·운영체제 화면은 웹 내 모의 화면으로 재현합니다. 원문에 없는 실제 책 제목·본문만 창작 예시로 대체합니다. 영화는 실제 재생하지 않습니다. 이동시간은 수동으로 압축합니다. 활동 결과는 원문 숫자를 무조건 표시하지 않고 체험 중 진행한 위치를 사용합니다.

피로도 3·5는 시나리오 배경이며 추가 입력 기능으로 만들지 않았습니다. 혼잡도 변화에 따른 오디오 전환, 경제 공부 활동, 음성, 별도의 콘텐츠 추천은 추가하지 않았습니다.

## 화면 우선순위

1. RETURN POINT: 원래 콘텐츠와 저장 위치를 확인하고 한 번 눌러 복귀
2. 활동 화면: 실제 페이지 조작·모의 영상 시청 위치 유지
3. 환승·도보 중단 상태: 활동을 강요하지 않고 저장 사실 전달
4. 시작·대기·의도 상기: 본래 활동에 진입하는 최소 흐름
5. 종료: 이어가기의 결과와 다음 위치 확인
